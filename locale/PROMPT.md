# פרומפט ל-ChatGPT

העתק את כל מה שבין הקווים, וצרף את הקובץ `he-source.json`.

---

אתה כותב תוכן (UX Writer) בעברית. אני שולח לך קובץ JSON עם כל הטקסטים שמופיעים במערכת ניהול אירועים וקמפיינים.

**מי המשתמשים:** מנהלות שיווק, אנשי תפעול ומכירות בחברת תווי שי. הם **לא אנשי טכנולוגיה**. הם פותחים את המערכת בבוקר כדי לראות מה קורה החודש ומה באיחור. אין להם סבלנות לקרוא, ואין להם מושג מה זה "ולידציה", "סנכרון" או "רשומה".

**המשימה:** לכל טקסט, מלא את השדה `"חדש"` בניסוח פשוט וטבעי יותר.

## איך לכתוב

**דבר כמו בן אדם, לא כמו מערכת.**
- ❌ "אירעה שגיאה בשרת" → ✅ "משהו השתבש. נסה שוב"
- ❌ "הנתונים שנשלחו אינם תקינים" → ✅ "יש שדה שצריך לתקן"
- ❌ "הרשומה עודכנה על ידי מישהו אחר" → ✅ "מישהו אחר שינה את זה בינתיים. רענן את הדף"

**כפתורים — פועל אחד, מה יקרה כשלוחצים.**
- ❌ "יצירת אירוע" → ✅ "צור אירוע" או "הוסף"
- ❌ "הוספת משתמש" → ✅ "הוסף אדם"

**שגיאות — מה קרה ומה לעשות. בלי האשמות.**
- ❌ "כתובת מייל לא תקינה" → ✅ "נראה שחסר משהו בכתובת. בדוק שיש @"
- ❌ "חובה להזין שם לאירוע" → ✅ "איך לקרוא לאירוע?"

**קצר. אם אפשר להוריד מילה — תוריד.**
- ❌ "לא נמצאו אירועים התואמים את המסננים שנבחרו" → ✅ "אין אירועים שמתאימים לחיפוש"

**פנייה ישירה בלשון יחיד.** לא "המשתמש יכול", אלא "אתה יכול" — או בלי גוף בכלל.

**בלי מילים טכניות.** אין: ולידציה · רשומה · שרת · API · סנכרון · אימות · ישות · שאילתה · לוג · סשן.

## מה אסור לשנות

בקובץ יש מפתח `מונחי_מוצר_שאסור_לשנות`. אלה מונחים שהצוות משתמש בהם בעבודה היומית — **השאר אותם בדיוק כמו שהם**, גם אם הם נשמעים מסורבלים. שינוי שלהם יבלבל אנשים שכבר רגילים אליהם.

## מבנה הקובץ

```json
"טקסטים": {
  "מסך כניסה": {
    "הטקסט הנוכחי": { "מיקום": "כפתור", "חדש": "" }
  }
}
```

השדה `מיקום` אומר לך איפה הטקסט מופיע. זה משנה את הניסוח:

| מיקום | איך לכתוב |
|---|---|
| `כפתור` | פועל, 1-3 מילים |
| `כותרת` | שם קצר, בלי נקודה בסוף |
| `תווית שדה` | מה מזינים כאן, 1-3 מילים |
| `placeholder (טקסט רפאים בשדה)` | דוגמה אמיתית, לא הוראה |
| `הודעת שגיאה` / `שגיאה` | מה קרה + מה לעשות |
| `הודעת הצלחה` | 1-3 מילים. "נשמר", "נמחק" |
| `aria-label (לקורא מסך)` | תיאור מדויק — נקרא בקול לעיוורים |
| `tooltip` | מה הכפתור עושה, קצר |
| `הסבר מתחת לשדה` | משפט אחד שמסביר למה זה חשוב |

## הכללים הטכניים

1. **החזר את אותו JSON בדיוק**, עם `"חדש"` מלא. אל תשנה מפתחות, אל תוסיף, אל תסיר.
2. אם טקסט כבר טוב — העתק אותו כמו שהוא לשדה `"חדש"`. אל תשאיר ריק.
3. שמור סימנים כמו `@`, `%`, מספרים ותאריכים.
4. אל תוסיף אימוג'ים.
5. שמור על עקביות: אם תרגמת "מחיקה" ל"מחק" במקום אחד — תעשה כך בכל מקום.
6. אל תשנה שמות חודשים או תאריכים עבריים.

## הפורמט של התשובה

רק ה-JSON. בלי הסברים לפניו ואחריו.

אם הקובץ ארוך מדי לתשובה אחת — החזר מסך אחד בכל פעם, לפי הסדר בקובץ, וחכה שאבקש את הבא.
